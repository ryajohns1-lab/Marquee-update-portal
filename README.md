# Fire TV Update Portal

A static, mobile-friendly GitHub Releases website. **This is a working starter website, not an already-deployed service, and it does not modify your Fire TV app.**

## Setup

1. Edit `config.js` with your public GitHub username, public repository, and release APK filename. The app must be in a **published, non-prerelease GitHub Release** with an APK attached. Normal Git pushes and ephemeral Actions artifacts are **not** releases.
2. Put these four website files in a GitHub Pages-enabled repository (or a `/docs` directory of your existing repository), and enable Pages under Settings > Pages. A separate public website repository is recommended if your app source repository is private.
3. Have your Beelink's CI script, after a successful build and signing, publish the APK to a GitHub Release (example: `gh release create v1.2.3 ./app-release.apk --title 'v1.2.3' --notes 'Changes'`). Configure `gh auth` securely and use a separate release tag each time.
4. In your Fire TV Android app, implement an updater that checks a release metadata endpoint, compares the remote `versionCode` against the installed `versionCode`, downloads the APK over HTTPS, verifies the checksum and signing identity, then launches the Android package installer. The user may need to explicitly permit/install the update on Fire OS.

## Important limitation of this starter

The website reads the public GitHub **latest-release** API, so it does not need a server. Your TV app can read the same API but this response is not a completed built-in Android updater. Release tags such as `v1.2.3` are **not** sufficient to reliably compare Android versions: best practice is a stable `update.json` (with integer `versionCode`, `versionName`, `apkUrl`, `sha256`, min supported app version), hosted on your website alongside this page and generated by your build script. Do not use HTML scraping to check versions. Keep the package name and signing key unchanged between app versions. Android and Fire OS generally require installation consent unless a specially provisioned/device-managed flow is available.

## Security

- Do not put GitHub access tokens, signing keys or server credentials in `config.js` or the website.
- For a private app, use an authenticated backend or distribution service rather than publishing a private repo token to the Fire TV app.
- Do not expose your Beelink on the public internet for the basic design; only outbound GitHub connections are needed.
